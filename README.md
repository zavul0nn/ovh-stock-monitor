# OVH VPS Stock Monitor

Монитор Linux VPS OVH 2027 с админским меню в Telegram и запуском через Docker Compose. По умолчанию проверяет VPS-2/3/4; в меню доступны VPS-1/2/3/4. Локации: LIM, RBX, GRA, SBG, WAW, ERI, MIL. Python 3.12, без сторонних Python-зависимостей.

## Автоматическая установка на Ubuntu

Поддерживаются Ubuntu 22.04 / 24.04 / 26.04 с systemd и обычным системным Docker. Распакуйте полный архив и запустите:

Из GitHub (если Git уже установлен):

```bash
git clone https://github.com/zavul0nn/ovh-stock-monitor.git
cd ovh-stock-monitor
sudo bash install.sh
```

Или из архива:

```bash
tar -xzf ovh-stock-monitor.tar.gz
cd ovh-stock-monitor
sudo bash install.sh
```

Установщик спросит токен бота (ввод скрыт), Telegram user ID администраторов и необязательные ID получателей. Всё остальное выполняется автоматически. Для установки без вопросов подготовьте `.env` по образцу `.env.example`:

```bash
sudo bash install.sh --env-file /absolute/path/to/bot.env
```

По умолчанию приложение размещается в **`/opt/ovh-stock-bot`**. Другой отдельный каталог можно указать через `--dir /opt/my-ovh-monitor`. Каталог с чужими файлами без метки установщика не принимается; символические ссылки в целевых путях также отклоняются.

Установщик:

1. Проверяет Ubuntu, параметры и отдельный каталог установки. Если Python 3 отсутствует, устанавливает его через APT с запретом удаления/обновления существующих пакетов.
2. Использует уже работающий Docker **без установки пакетов Docker, обновления движка или перезапуска службы**. Если имеющаяся системная служба Docker остановлена — запускает её командой `start`. Активную, но недоступную службу не перезапускает.
3. На чистой машине добавляет официальный APT-репозиторий Docker и устанавливает Engine/Compose/Buildx. Если найдены конфликтующие пакеты containerd/runc или другая незавершённая установка Docker, останавливается с объяснением вместо удаления/замены. APT-план проверяется перед установкой: удаление или обновление существующего пакета запрещено. Автоматический перезапуск служб через needrestart отключён для этих команд.
4. Если работающему Docker не хватает Compose или Buildx, скачивает только недостающий CLI-плагин из официального `docker/compose` или `docker/buildx`, проверяет SHA-256 из `checksums.txt` и устанавливает новый файл. Существующие плагины не обновляются. Ручные плагины не обновляются автоматически.
5. Создаёт `data/` с владельцем **10001:10001** и правами `700`. Изменяет права только самого каталога и известных файлов SQLite/lock, без рекурсивного chown. Если внутри найдены посторонние файлы/подкаталоги/ссылки — останавливается до изменения прав.
6. Копирует код в новый каталог `releases/`, собирает тестовый образ и запускает все автоматические тесты, затем собирает рабочий образ. До успешной сборки текущий контейнер монитора не заменяется.
7. Перед обновлением делает согласованную онлайн-копию существующей SQLite через SQLite Backup API в `backups/` и проверяет её целостность.
8. Запускает **только сервис monitor** в собственном Compose-проекте со случайным постоянным идентификатором. Проверяет метку принадлежности существующих контейнеров проекта. Порты наружу не публикуются. Ждёт `healthy` до трёх минут.

Нет команд `docker prune`, `docker compose down`, удаления volumes/контейнеров других проектов, `apt upgrade`, `autoremove`, перезапуска Docker или изменения `daemon.json`/firewall. Работа идёт с локальным системным сокетом Docker; переменные окружения с удалённым Docker context/host не направят установку на другой сервер. Rootless Docker и userns-remap требуют отдельной настройки путей/прав и этим установщиком не настраиваются.

Повторите ту же команду из распакованного **нового архива**, чтобы обновиться. Существующий `.env`, настройки, база и идентификатор Compose-проекта сохраняются; `--env-file` при повторном запуске не заменяет сохранённый `.env`. Старые релизы, образы и резервные копии автоматически не удаляются.

Управление установленным проектом:

```bash
sudo /opt/ovh-stock-bot/manage.sh ps
sudo /opt/ovh-stock-bot/manage.sh logs --tail=100 -f monitor
sudo /opt/ovh-stock-bot/manage.sh restart monitor
```

Данные находятся в `/opt/ovh-stock-bot/data/monitor.sqlite3` (bind mount), секреты — `/opt/ovh-stock-bot/.env` с правами `600`. `manage.sh` содержит точный путь к установленному релизу и его Compose-проекту. Изменения `.env` применяйте через `sudo /opt/ovh-stock-bot/manage.sh up -d --force-recreate monitor`.

Если тест/сборка не прошли, старый контейнер не заменяется. Если после запуска не получен `healthy`, установщик возвращает ошибку и команду просмотра логов, но сохраняет контейнер, данные и резервную копию. Автоматического отката схемы базы нет.

Установщик не переносит автоматически прежний запуск через обычный `compose.yaml` с named volume. Для такой установки продолжайте прежний способ обновления или переносите базу отдельно; запуск второго экземпляра с тем же Telegram-токеном приведёт к конфликту polling. Установщик не останавливает старый экземпляр сам.

Источники установки: [Docker Engine для Ubuntu](https://docs.docker.com/engine/install/ubuntu/), [Compose plugin](https://docs.docker.com/compose/install/linux/), [Buildx](https://github.com/docker/buildx#manual-download).

## Ручной запуск через Docker Compose

Нужны Docker Engine, Docker Compose v2 и отдельный Telegram-бот. Перенесите папку на сервер:

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

Обязательные параметры:

```dotenv
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_ADMIN_IDS=123456789
```

`TELEGRAM_ADMIN_IDS` — числовые **user ID** администраторов через запятую. Только эти пользователи могут открыть `/admin`, только в личной переписке с ботом. ID группы не является ID администратора. Чтобы узнать собственный ID у уже запущенного бота, отправьте `/id`; эта команда доступна всем, но не даёт права управления. Первого администратора нужно заранее указать в `.env`.

Необязательный `TELEGRAM_CHAT_IDS=123456789,-1001234567890` задаёт начальный список получателей. Если он пуст, получателями станут администраторы. Личный получатель должен нажать **Start** у бота, для группы/канала боту нужны права отправки. Администраторы и получатели — разные списки: получатель не получает права менять настройки.

```bash
docker build --target test -t ovh-stock-tests .
docker compose build
docker compose run --rm monitor check
docker compose run --rm monitor test-notification
docker compose up -d
docker compose logs --tail=50 -f monitor
```

Откройте личный чат с ботом и отправьте `/admin` или `/start`.

## Админское меню

| Раздел | Действия |
|---|---|
| Интервал | Кнопки 1/2/5/10/30/60 минут; ввод любого целого N от 1 до 1440 минут |
| Тарифы | Включение и отключение VPS-1/2/3/4; минимум один включённый тариф |
| Получатели | Добавить себя, добавить несколько числовых ID через пробел/запятую, удалить с подтверждением, отправить тест всем |
| Статус | Текущий интервал, последние проверки выбранных тарифов, размер очереди и чаты с ошибками доставки |

Настройки применяются без перезапуска и хранятся в SQLite. Интервал отсчитывается от завершения предыдущей проверки каждой модели. Уменьшение интервала ускоряет следующую проверку, увеличение откладывает её; `Retry-After` источника продолжает соблюдаться. Чтение новых настроек занимает обычно до секунды, при текущем запросе — до его завершения.

При включении тарифа проверяются и уже доступные VPS. Отключённый тариф больше не опрашивается; ответ запроса, начатого при старых настройках, не создаёт новые события. Активные напоминания этого тарифа отменяются. Уже поставленные в очередь разовые сообщения могут быть доставлены позже с исходным временем события.

Новые получатели получают подтверждение добавления, затем **будущие события**. Старое наличие и история уведомлений автоматически им не рассылаются. Кнопка «Тест всем получателям» проверяет отправку отдельно от появления VPS. Сообщение «поставлено в очередь» ещё не означает доставку.

Список получателей имеет постраничный просмотр. Удаление отменяет ожидающие сообщения этому чату. Если запрос отправки уже ушёл в Telegram, остановить его задним числом нельзя. Можно удалить всех получателей; меню явно покажет, что уведомления о наличии отправлять некому. Само меню остаётся доступным администратору.

Ввод числа/ID действует 10 минут, отдельно для каждого администратора. `/cancel` отменяет ввод. Изменение настройки и сохранение номера обработанного Telegram update происходят одной транзакцией; повторное получение того же update не повторяет действие.

Бот использует `getUpdates` (long polling), входящие порты не нужны. Для этого токена не должен работать другой polling-процесс или webhook: при конфликте Telegram вернёт ошибку, она попадёт в логи. Бот не удаляет чужой webhook автоматически.

## Надёжность доставки

### Появление, подтверждение и исчезновение

При первом запуске доступные локации одного тарифа объединяются в одно сообщение с кнопкой **«✅ Я увидел уведомление»**. Сообщение повторяется через 60 секунд после успешной отправки и далее каждую минуту, пока получатель не подтвердит его или монитор не обнаружит исчезновение VPS. Интервал напоминаний фиксирован и не зависит от настроенного интервала опроса OVH.

Подтверждение действует только для данного появления и данного чата. Проверки всех выбранных тарифов, включая подтверждённый, продолжаются. В личном чате подтвердить может сам получатель, даже если он не администратор; в группе или канале — пользователь из `TELEGRAM_ADMIN_IDS`. Нажатие старой кнопки после исчезновения и нового появления не отключает новый цикл.

При переходе из `available` в отсутствие/предзаказ отправляется **одно** сообщение «пропал» без кнопки. Оно отправляется и после подтверждения предыдущего появления. Ожидающие напоминания об исчезнувшем наличии отменяются. Повторные проверки отсутствия не создают новых сообщений. При новом появлении создаётся новый цикл с новой кнопкой.

Если из пяти локаций пропала одна, сообщение об исчезновении перечислит её; неподтверждённые напоминания продолжатся только для оставшихся. Новая локация, появившаяся позднее, получает отдельный цикл. Пример: подтвердили VPS-1 в LIM/GRA → появился VPS-2 в WAW → напоминания о VPS-2 → VPS-1 пропал в LIM → одно сообщение об исчезновении → VPS-1 снова появился в LIM → новый цикл напоминаний.

Подтверждения и сроки напоминаний сохраняются после перезапуска. При недоступном Telegram не накапливаются одинаковые минутные сообщения: для каждого цикла и чата хранится максимум одно ожидающее напоминание. Уже отправленный HTTP-запрос нельзя отменить — при одновременном подтверждении/исчезновении и отправке возможно одно сообщение в пути.

При опросе раз в N минут исчезновение будет обнаружено только на следующем успешном опросе. До этого напоминания опираются на последнюю проверку, время которой указано в тексте. Ошибка API сама по себе не считается исчезновением.

- Прямой публичный API OVH `/vps/order/rule/datacenter` с `ovhSubsidiary=IE`. Ключи OVH не нужны. Учитывается `linuxStatus`, а не общий статус или наличие Windows. `out-of-stock-preorder-allowed` считается предзаказом, а не наличием.
- Изменение наличия и уведомления для **каждого** получателя сохраняются одной транзакцией. Telegram должен подтвердить `ok: true`, прежде чем соответствующая отправка будет завершена; следующий повтор запланируется через минуту, если пользователь ещё не подтвердил.
- Ошибка одного чата не блокирует другие. Повтор через 5, 10, 20… секунд, максимум 300 секунд, либо позже согласно `retry_after`. Порядок сохраняется внутри каждого чата. Общая скорость — примерно одно сообщение в 1,1 секунды. При большом числе получателей доставка последним займёт больше времени.
- Отправка Telegram и админское меню работают в отдельных потоках от опроса OVH. Очередь переживает перезапуск и ошибки сети. При исчезновении актуальные напоминания заменяются однократным сообщением об исчезновении.
- Неполный ответ OVH, неизвестный статус, отсутствие `linuxStatus` или повторяющийся DC не затирают состояние. При изменении API может потребоваться обновить код. Другие модели продолжают проверяться.
- После 180 секунд ошибок источника создаётся предупреждение; после восстановления — сообщение о восстановлении. Раз в сутки приходит сообщение с временем последних проверок.
- Healthcheck учитывает выбранные тарифы, настроенный интервал, свежесть polling-потока меню, отправителя и возраст очереди. Ошибки доставки можно посмотреть в разделе «Статус» и логах.

Абсолютной гарантии поймать каждый остаток нет: VPS может исчезнуть между опросами, API и сеть могут задержать ответ. Монитор не резервирует и не покупает VPS. Интервал 1 минута уменьшает окно пропуска по сравнению с 5–30 минутами.

При разрыве после успешной отправки Telegram, но до фиксации результата в SQLite возможен дубль: здесь нет ключа идемпотентности Telegram. Выбрана повторная доставка вместо риска молча потерять событие. Для обнаружения полного отключения сервера нужен внешний контроль: выключенный бот не сможет сообщить о собственном падении.

## Обновление существующей установки

Добавьте `TELEGRAM_ADMIN_IDS` в существующий `.env`, затем:

```bash
docker compose up -d --build
```

Старый `TELEGRAM_CHAT_ID` поддерживается как начальный получатель. Старая очередь автоматически получает адреса начальных получателей при миграции; таблица наличия сохраняется. После первой настройки SQLite имеет приоритет над `TELEGRAM_CHAT_IDS` и `POLL_INTERVAL_SECONDS`: эти параметры только начальные. Права администраторов всегда берутся из `.env`; после их изменения выполните `docker compose up -d --force-recreate`.

Docker volume `stock-data` содержит настройки, очередь и состояние. Обычный `docker compose down` сохраняет его. **`docker compose down -v` удалит эти данные.** Старый JSON-файл исходного скрипта не импортируется. Старый systemd-таймер нужно остановить, чтобы не работали два монитора.

```bash
docker compose ps
docker compose logs --tail=100 monitor
docker compose exec monitor python monitor.py healthcheck
docker compose restart monitor
```

`check` проверяет выбранные в базе тарифы, а до первого запуска — VPS-2/3/4; ничего не отправляет. `test-notification` отправляет тест текущим получателям из базы, а до первого запуска использует `.env`.

Контейнер работает от непривилегированного пользователя с файловой системой только для чтения вне `/data` и `/tmp`. Compose перезапускает завершившийся процесс через `restart: unless-stopped`; один только статус `unhealthy` не перезапускает процесс. См. [Docker restart](https://docs.docker.com/reference/compose-file/services/#restart) и [HEALTHCHECK](https://docs.docker.com/reference/dockerfile/#healthcheck).

Для установщика проверены ветки чистой машины/существующего Docker/конфликтующего runtime, запрет обновлений и удалений APT, сохранение конфигурации, права только на свои файлы, резервная копия SQLite, принадлежность Compose-проекта, проверка SHA-256 плагинов и остановка до замены контейнера при ошибке тестов. Команды APT/Docker/systemd в этих тестах заменены имитациями; реальные системные службы не изменялись. `install.sh` дополнительно прошёл проверку `bash -n`.

```bash
python -m unittest discover -s tests -v
python tests/live_check.py
```

Живой тест VPS-1 повторяется отдельно от автоматических тестов. Проверяет настоящее наличие, группировку доступных локаций в одно сообщение с кнопкой, отсутствие дублей при повторном опросе, сохранение очереди после искусственного HTTP 500 и переоткрытия базы. Получатель — локальный HTTP-сервер, заменяющий Telegram. Последний результат и время: `live-test-result.json`. Используется временная база; рабочие настройки не меняются. Если доступного VPS-1 нет или наличие меняется между двумя опросами, стабильный положительный сценарий потребует повторного запуска.

GitHub Actions на Ubuntu успешно выполнил тесты внутри Docker, сборку рабочего образа, проверку Compose и запуск рабочего образа для проверки импорта приложения: [успешный прогон](https://github.com/zavul0nn/ovh-stock-monitor/actions/runs/34027397375). **Полная установка через APT/systemd на настоящую Ubuntu пока не проверена** — эти операции установщика тестировались с имитациями. Сам установщик запускает тесты в Docker до развёртывания. Реальное отображение кнопок в Telegram и доставка вашему боту требуют его реквизитов и ещё не проверены.

Контракты: [OVH VPS API](https://eu.api.ovh.com/1.0/vps.json), [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates), [InlineKeyboardMarkup](https://core.telegram.org/bots/api#inlinekeyboardmarkup), [sendMessage](https://core.telegram.org/bots/api#sendmessage).
